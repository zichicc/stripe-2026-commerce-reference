1. Zero Trust on Client-Side Amounts

Never accept amount or price from the browser request body

Minor Units (Cents)

The browser only sends sku_id + quantity. The backend looks up the canonical price in the server-side CATALOG in integer minor units (e.g., 84900 for $849.00) and computes tax and FX server-side. Any request containing amount or price is rejected with HTTP 400.

2. Deterministic Idempotency-Keys

f"pi_create_{order_id}_attempt_{attempt_no}" · 24-Hour TTL

Zero Double-Charge

Never generate a random uuid4() inside a retry loop! Deterministic keys tied to the business entity ensure network retries replay the cached response for 24 hours, while reusing the same key with modified parameters triggers HTTP 400 idempotency_error.

3. Raw-Body Webhook HMAC (Stripe-Signature)

stripe.Webhook.construct_event(raw_body, sig, secret) · 300s Window

HMAC-SHA256

Always pass the unparsed raw byte payload (await request.body()), never a re-serialized JSON dictionary, into construct_event(). Enforces HMAC-SHA256 authenticity and a 300-second (5-minute) timestamp tolerance against replay attacks.

4. Idempotent & Async Webhook Fulfillment

INSERT INTO processed_events ... ON CONFLICT DO NOTHING · <200ms ACK

72h Retry Safe

Stripe retries unacknowledged webhooks for up to 72 hours with exponential backoff and does not guarantee event ordering. Deduplicate event.id in the database, enqueue fulfillment to an async background worker, and return HTTP 200 within <200ms.

5. Granular Stripe Exception Taxonomy

CardError (402) vs RateLimitError (429) / APIConnectionError

Backoff + Jitter

Explicitly distinguish business declines (stripe.error.CardError HTTP 402 — never auto-retry; return user-friendly message & increment attempt_no) from transient errors (RateLimitError 429 & APIConnectionError — retry with exponential backoff + jitter using the same Idempotency-Key).

6. Eliminating N+1 Calls with expand[] & Cursors

expand=['latest_charge.balance_transaction'] & starting_after

1 HTTP Round-Trip

Fetch a PaymentIntent and its nested latest_charge.balance_transaction (net fee + FX rate) in a single HTTP request instead of 3 sequential calls. Use cursor pagination (starting_after='pi_...' or auto_paging_iter()) for list endpoints.

7. Structured metadata Propagation for Webhooks & BigQuery Data Pipeline

metadata={'order_id': order_id, 'customer_tier': 'enterprise', 'erp_cost_center': 'IT-01'}

Zero-Lookup Joins

Attach structured business metadata across every PaymentIntent, Charge, TaxCalculation, and Transfer so downstream webhook consumers and BigQuery Data Pipeline tables join ledger records directly without external database lookups.
